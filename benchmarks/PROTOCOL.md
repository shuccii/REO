# Public evaluation protocol

The primary cases in `cases.py` use only synthetic or frozen public fixtures. `research_strict_defects` covers leakage, circular target construction, test-set selection, invalid nominal optimization, missing uncertainty, consequential imputation, physical impossibility, category duplication, extrapolation, retrospective rediscovery, and invalid downstream interpretation. The two holdout cases are excluded from tuning and run only after the primary gate passes. Files named `benchmarks/private.local.*` are optional local regressions and are never part of the public release claim.

Critical rubric items cover exact value preservation, required implementation/test artifacts, frozen-source facts and citations, every planted defect ID, absence of false positives, and absence of a submission marker. Pre-fixed noncritical items cover terminal newline quality; named edge-case coverage in code tests; explicit source-conflict and supersession explanation; and documented corrections tied to every detected defect ID. `cases.py` emits the item vector as well as its score, so noncritical comparison is not a constant placeholder.

Formatting also requires zero observed collaboration calls (including empty waits), checked from CLI events by the harness. Both observed `collab_tool_call` and `collab_agent_tool_call` variants are recognized. Event and spawn-call counts are observations, not a claim of complete subagent or semantic-review coverage. A schema-adapter correction invalidates earlier sessions for release comparison; retain them as diagnostic history and start a new frozen session.

The independent-module case requires a manifest that records `names.py` and `stats.py` as independent write scopes. A collaboration wait without a concrete receiver or reported agent state is a critical failure; prose claiming that a worker or reviewer ran cannot replace an observed identity. When spawning is unavailable, direct implementation may still produce reviewable artifacts, but in-run semantic review remains outstanding until an identifiable reviewer supplies evidence.

For v0.3 workflow conformance, strict research and implementation scopes require integration-eligible v0.3 semantic-review results whose independent reviewer identity appears in host-observed collaboration events. Missing review is a critical failure, even if external artifact adjudication passes. Historical results are archive evidence and are not required to adopt the new schema. The common evaluator hash also covers its trusted imported validators and schemas.

Run deterministic checks with `python3 scripts/run_checks.py`. Create preliminary v0.1 measurements with `python3 benchmarks/harness.py pilot --output baseline`. For a release comparison, use a fresh directory and run `python3 benchmarks/harness.py compare --output benchmark-results/<session>`. Each case gets three paired executions, with version order alternating. The harness invokes a fresh ephemeral Codex process, injects the selected frozen skill text, records host-side time and CLI events, and never imports or executes agent-generated code.

Generate `adjudications.template.jsonl` with the `adjudication-template` mode. An independent reviewer must inspect retained workspaces and replace every placeholder with a run-bound decision. `report` rejects missing, duplicate, cross-session, or malformed adjudications. Raw workspaces and events are local-only and gitignored.

Release requires all v0.3 critical checks, all strict-research defect IDs, no false positives, no noncritical-score regression against the comparison baseline, and accepted semantic adjudication. Performance reporting remains paired and versioned, but research correctness gates take precedence over speed. Infrastructure failures are reported as insufficient measurement rather than success.

After primary success, run `holdout` without changing the working pack. It records a separately identified holdout session and exits nonzero while semantic review is pending. Add the run-bound adjudication, then run `holdout-report`; it checks the primary pack hash, every critical check, and required independent review. Any quality failure, speed failure, or insufficient measurement leaves v0.1.0 installed.

`active_wall_clock` currently equals child-process elapsed time because the noninteractive harness has no human approval channel; `approval_wait` is therefore zero with an explicit basis. LLM calls, reviewer count, subagent count, observed model identity, and cost remain null when the CLI does not expose them. They are never inferred from turn or tool counts.
