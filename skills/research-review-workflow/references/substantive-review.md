# Substantive review procedure

Use for Standard/Deep audits, peer reviews and supervision. The entrypoint invariants apply to every step.

1. Establish stage, question, central claims, audience, version and resources. Resolve the user's supplied `RESEARCH_REVIEW_CONTEXT.md`, applicable degree/venue criteria and registered policies. When earlier reviews or local context exist, read `local-context-and-continuity.md`, the configured current-state, known-issues and relevant prior-feedback records. Do not infer present resolution from old reports. Use topic-specific primary sources where evidence is needed; the static public-source index is only a retrieval lead.
2. Reconstruct problem → gap → question → method → observation → inference → contribution. Assign claim IDs and exact page/figure/code/data locators. Preserve supported strengths and bounded conclusions.
3. Read `assessment-rubric.md`, `phase-expectations.md`, `output-template.md` and at most one or two relevant probes. Evaluate the ten dimensions; mark assessed, partial, unassessed or not applicable with reasons. An interim review judges justified progress and feasibility, not completed-thesis expectations.
4. Seek alternatives, counterexamples and boundary conditions for central claims. Check applicable derivations, dimensions, assumptions, independent units, fair baselines and evaluation scope. Execute calculations before numerical findings and retain command/value/evidence. Reproduction proves execution, not validity. Missing runtime/raw data leaves that numerical dimension unassessed without blocking unrelated document critique.
5. Obtain complementary independent review when conclusions are consequential; select it by risk (use `tools/review_routing.py` when available). Delegates inspect their own evidence and have distinct scopes. Agreement is not independent scientific evidence. Retain substantive disagreements; if independent review is unavailable, label the report lead-only preliminary and leave that gate pending.
6. Each finding identifies claim, locator, certainty, severity, mechanism, correction, rerun scope and acceptance condition. Prioritize conclusion-changing defects. Do not silently change the research question after seeing the results.
7. Use the fixed output template for Standard/Deep. For repeats, map prior findings to current evidence: new / known unresolved / partially improved / resolved / recurred / unverified (the Japanese template uses its corresponding labels). Do not claim resolution without fresh inspected evidence. Keep private locators in user-local reports. Save only when requested.
8. For durable formal JSON, read `review-report-contract.md` and `assets/research-review.schema.json`, then run its validator. JSON validation checks declared relationships/readiness, not source truth. Executing experiments, fitting, statistical inference or integrating scientific results still requires `research-ml-workflow` and its research_strict manifest/contract and independent semantic review. Pure document review may finish within a clearly limited scope.

Separate the readiness of this review, scientific support for each claim, actual faculty approval and permission to publish/submit. Never infer one from another or from an AI score.
